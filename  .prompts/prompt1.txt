Prompt 1 — Manifest contract and validator

Goal:
Create one machine-enforced adapter manifest contract and a validator. Work on a branch and show the diff before any push or merge. If running in a code-writing agent that can open PRs, create a branch and a single PR per this task only after user confirmation.

Files to produce (exact paths):
- schemas/adapter_manifest.schema.json
- models/adapter_manifest.py
- scripts/validate_manifest.py
- tests/test_manifest_validation.py
- requirements-dev.txt (only if missing)
- docs/SCHEMA_EVOLUTION.md (small seed with schema_version policy)

Key requirements:
1. Use JSON Schema Draft 2020-12. In the JSON Schema include a required "schema_version" field. Seed with "schema_version": "2026-08-1".
2. Fields required and types:
   - schema_version (string)
   - adapter_id (string) — require regex ^[0-9a-f]{16}_[0-9a-f]{16}$ OR allow a documented fallback when explicitly provided as "adapter_id_human_fallback" in manifest (document this in SCHEMA_EVOLUTION.md).
   - created_at (RFC3339 timestamp string)
   - source_fingerprint (string)
   - target_fingerprint (string)
   - mapping_policy (object)
   - dependency_versions (object)
   - validation_authority (string)
   - models_used (array[string])
   - synthesis_mode (string, enum: ["single_pass", "two_pass", "repair_attempt"])
   - context_references (array[string])
   - fixture_ids (array[string])
   - test_result (enum: ["passed", "failed", "skipped"])
   - lossiness (array[string])
   - redactions (array[string])
   - status (enum: ["proposed","valid","stale","invalid","deprecated"])
   - optional generator metadata under "generator": { name, version, prompt_hash } permitted but not required.

3. Implement models/adapter_manifest.py using Pydantic v2 (BaseModel from pydantic) and include:
   - strict typing and validators that mirror the JSON Schema rules (e.g., regex for adapter_id, timestamp parsing).
   - a top-level function validate_manifest(path_or_dict) -> (is_valid: bool, errors: list[dict]) with structured error messages.
   - include a small helper to render differences between JSON Schema validation and Pydantic validation if they disagree.

4. scripts/validate_manifest.py:
   - CLI usage: python scripts/validate_manifest.py adapters/<adapter_id>/manifest.json
   - When run with a directory root it should validate all adapters/*/manifest.json
   - Exit codes: 0 = all valid, 2 = validation error(s) found, 3 = usage/error
   - Print structured JSON errors when invalid (no secrets echoed).

5. Tests:
   - tests/test_manifest_validation.py must include:
     - One valid manifest test (use the example from skills/SEMANTIC_OS.md or the weather manifest).
     - At least three negative tests: missing required field; wrong type; invalid enum/status.
   - Tests must not execute any adapter code.

6. SCHEMA_EVOLUTION.md:
   - Simple policy: bump schema_version for non-breaking docs edits vs breaking changes. Describe how to indicate backwards-incompatible changes and a migration path.

Safety + guardrails:
- Do not modify adapter implementations, audit records, or fixtures.
- Do not attempt to auto-fix manifests.
- Add a header comment to generated files: "Generated by Manus-assisted change — review required" (or analogous for manual runs).
- Do not add a license file.

Acceptance criteria (what to verify locally):
- jsonschema.validate and the Pydantic model must accept the valid fixture and reject the invalid ones with clear errors.
- The CLI returns exit code 0 for valid manifests and 2 for invalid.
- pytest passes locally.

Branching/PR guidance:
- Suggested branch name: feat/manifest-validator
- Suggested commit message: "chore: add manifest JSON Schema, Pydantic model, validator CLI, and tests"
- If automating: create a single PR containing these changes; include SCHEMA_EVOLUTION.md and required tests.
